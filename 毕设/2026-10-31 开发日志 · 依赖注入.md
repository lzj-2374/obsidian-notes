# Spring 依赖注入：构造器注入 vs @Autowired 字段注入

> 记于 2026-10-31，写个人中心接口时遇到的实际问题。

## 两种写法

```java
// 写法 A：字段注入
@Autowired
private UserService userService;

// 写法 B：构造器注入（注意没有 @Autowired）
private final StatisticsService statisticsService;

public StatisticsController(StatisticsService statisticsService) {
    this.statisticsService = statisticsService;
}
```

两种都能跑，效果完全一样。但 Spring 官方从 4.3 起推荐 B。

## 为什么单个构造器可以不写 @Autowired

Spring 4.3 之后有一条规则：**一个类如果只有一个构造函数，容器创建它时会自动把参数对应的 bean 注入进去**，注解可以省略。

只有这两种情况才非得写 `@Autowired`：

- 一个类里有**多个构造器**，Spring 不知道用哪个，得用 `@Autowired` 标出选中的那个
- 用的是字段注入（写法 A），那必须写

关键点：不是"不能用 @Autowired"，是**不需要**。写了也不报错，只是多余。

## 构造器注入的四个好处

### 1. 字段能声明成 final

字段注入的值是在对象造好之后用反射硬塞进去的，构造那一刻还是 null，所以加不了 `final`。

构造器注入在对象出生那一刻就赋好值了，可以写 `private final`，等于声明"这个依赖一辈子不变"。

### 2. 依赖清单写在明面上

看构造器的参数列表就知道这个类依赖谁，一眼能数出来。

如果某天构造器里有 8 个参数，说明这个类职责太重、该拆了。字段注入把这个信号藏在类体中间，扫一眼发现不了。

### 3. 单元测试能直接 new

```java
// 构造器注入：直接 new，塞个假的进去
StatisticsController controller = new StatisticsController(new FakeStatisticsService());

// 字段注入：得启动 Spring 容器，或者用反射往私有字段里塞
```

前者毫秒级，后者要拉起整个 Spring 上下文，慢几十倍。

### 4. 循环依赖在启动时就暴露

如果 A 的构造器要 B、B 的构造器要 A，构造器注入在启动那一刻直接报错。字段注入有时候能蒙混过关，等运行时某个方法炸了才发现，排查成本高得多。

## 项目里的现状

| 类 | 注入方式 |
|---|---|
| `UserController` | 字段注入 `@Autowired`（早期写的） |
| `UserServiceImpl` | 构造器注入 |
| `StatisticsController` | 构造器注入 |
| `StatisticsServiceImpl` | 构造器注入 |

两种混着不影响功能。新写的类统一用构造器，老的不用急着改。

## 面试怎么答

被问"为什么用构造器注入"，按这个顺序说：

1. 依赖不可变，字段能声明成 `final`
2. 依赖关系显式化，构造器参数就是依赖清单
3. 便于单元测试，不需要启动容器
4. 循环依赖能在启动阶段暴露

如果被追问"@Autowired 有什么问题"，答：依赖被隐藏了、无法 final、单测要拉容器，而且它是在对象构造完之后才注入，构造方法里如果用到这个依赖会拿到 null。
