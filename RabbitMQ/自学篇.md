**1，创建配置类：**
向RabbitMQ申请一个队列demo.hello
```java
package com.example.mqdemo;

import org.springframework.amqp.core.Queue;
import org.springframework.amqp.core.QueueBuilder;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

/**
 * 第 1 张卡：向 RabbitMQ 申请一个队列。
 *
 * 这个类里没有任何业务逻辑，不算数、不收消息、不发消息，
 * 只在项目启动那一刻跑一次，把下面这个 Queue 对象登记给 Spring。
 * Spring 启动时会由 RabbitAdmin 自动连到 MQ，把队列真正建出来，
 * 所以不用去管理台手动点 New Queue。
 */
@Configuration
public class MqConfig {

    /**
     * 队列名只写这一处。后面生产者发消息、消费者监听都引用它，
     * 避免同一个字符串散在两个类里，改一处漏一处还不报错。
     */
    public static final String QUEUE = "demo.hello";

    /**
     * @Bean = 登记一行：Spring 启动时会调用这个方法一次，把返回值收进自己的柜子。
     * 方法名 demoQueue 就是柜子里这个名字，随便起都行。
     *
     * durable(...) = 持久化队列，RabbitMQ 重启后队列还在。
     */
    @Bean
    public Queue demoQueue() {
        return QueueBuilder.durable(QUEUE).build();
    }
}
```
产出：
1.确认 RabbitMQ 起到（浏览器能开 http://localhost:15672）
2.右键 MqDemoApplication → Run
3.管理台 → Queues 页，应该出现 demo.hello，Features 列带个 D（durable）

**2，往demo.hello里发送一条消息：**
新建一个MqSender类：
```java
package com.example.mqdemo;

import org.springframework.amqp.rabbit.core.RabbitTemplate;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class MqSender {
    private final RabbitTemplate rabbitTemplate;

    public MqSender(RabbitTemplate rabbitTemplate) {
        this.rabbitTemplate = rabbitTemplate;
    }

    @GetMapping("/send")
    public String send(){
        rabbitTemplate.convertAndSend(MqConfig.QUEUE,"hello lzj");
        return "ok";
    }

}
```
产出：
访问 `http://localhost:8081/send`，然后刷新管理台：`demo.hello` 的 **messages 从 0 变 1**，再访问一次变 2。消息堆着没人取，正好把「队列才存消息」变成看得见的数字。

@Bean

**5，故意让消费失败一次：**

5.1，在MqReceiver的`System.out.println(taskMsg);`后面加一句：
```java
throw new RuntimeException("失败");
```
5.2，将项目停止后重启
产出：
浏览器 http://localhost:15672 刷新后控制台出现：同一条 `TaskMsg(taskId=1001)` 被反复打印，中间夹着 WARN 重试日志(一直刷屏)

**6,解决办法：**

在yml里面加：
```yaml
spring:
  rabbitmq:
    # ……原来的 host / port / 账号都别动……
    listener:
      simple:
        default-requeue-rejected: false
        retry:
          enabled: true
          max-attempts: 3
          initial-interval: 1000ms

```
retry.enabled: true：打开消费者本地重试（在当前线程里重试，消息不回队列）
max-attempts: 3：含第一次，最多试 3 次就认输
initial-interval: 1000ms：每次之间等 1 秒，不再瞬间刷屏
default-requeue-rejected: false：兜底：认输之后别把消息放回队列（放回去就又回到无限循环）

产出：
改完后重启，浏览器刷新后，
控制台打印 3 次 TaskMsg(taskId=1001)，间隔 1 秒、2 秒，然后停
管理台 messages 归 0，不再在 0/1 之间跳
日志里能看到重试耗尽的 WARN，而不是无休止的刷屏

**提示：**==3 次用完，消息就会被丢弃==
消息不是"自己蒸发"的，是 Spring 替你做了"扔掉"这个决定：
消费方法抛异常 → 重试 3 次还是失败，这时候 Spring 必须给这条消息一个交代，而它只有两个按钮：
1，放回队列（requeue = true）：消息重新排队 → 又消费 → 又抛异常 → 又放回……就是上一张卡的无限刷屏
2，拒收不要（requeue = false）：告诉 RabbitMQ「这条我不要了，别再给我」
而yml中`default-requeue-rejected: false`就明确了拒收不要，因此消息不是意外丢失的，是为了止血主动选的。

不解的地方：
打印在了控制台，为啥算是丢失了，一开始没模拟消费失败不是也打印在了控制台吗，没模拟前的消息还能在哪找到呢？

解答：
关键：打印 ≠ 消息还在
System.out.println(taskMsg) 只是把内容抄了一份写到屏幕上。抄完，那份文字留在 IDEA 控制台里；而 MQ 里的那条消息是另一个东西，它的命运由 ACK 决定，跟打不打印毫无关系。

**两条路径，终点其实一样：**

| | 正常消费（没模拟失败） | 重试 3 次仍失败 |
|---|---|---|
| 打印 | 打印了 | 也打印了（3 次） |
| 消费者给 MQ 的回话 | 「办好了，确认收货」(ack) | 「办不了，别再给我」(nack) |
| 消息在队列里 | **被删除** | **也被删除** |
| 区别 | 事情真的办成了 | **事情没办成，也没人再管了** |
