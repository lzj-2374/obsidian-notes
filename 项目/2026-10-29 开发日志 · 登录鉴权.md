## 一、实体与 Mapper

6 个实体类，字段与建表脚本逐列对齐（依赖 MyBatis-Plus 默认的 `map-underscore-to-camel-case`）。

- 统一 `@Data` + `@TableName` + `@TableId(type = IdType.AUTO)`
- **逻辑删除只给 `User` / `Clothing` / `ClothingCategory` / `Outfit`**
- `ClothingTag` / `OutfitItem` **不带** `@TableLogic`：这两张走物理删除。原因是 `outfit_item` 上有唯一索引 `uk_outfit_role (outfit_id, role)`，做逻辑删除后"删掉旧上装换新的"会撞索引报 `Duplicate entry`
- `User.password` 加 `@JsonIgnore`，任何接口返回 User 都不会带出密码

Mapper 全部 `extends BaseMapper<T>` + `@Mapper`，单表增删改查白拿。

## 二、统一响应与异常体系

```
common/
├── Result.java                  统一结构 {code, message, data}
├── ResultCode.java              业务错误码枚举（分段）
├── BusinessException.java       业务异常，继承 RuntimeException
└── GlobalExceptionHandler.java  全局异常转 Result
```

### 错误码分段约定

| 区间 | 模块 | 示例 |
|---|---|---|
| 200 | 成功 | `SUCCESS` |
| 4xx | 通用 | `PARAM_ERROR` / `UNAUTHORIZED(401)` / `SYSTEM_ERROR(500)` |
| 1xxx | 用户 | `USERNAME_EXISTS(1004)` / `PASSWORD_ERROR(1006)` |
| 2xxx | 衣柜 | `CLOTHING_NOT_FOUND(2001)` |
| 3xxx | 搭配 | `OUTFIT_NOT_FOUND(3001)` |

`UNAUTHORIZED` **必须是 401**，因为前端拦截器写死了 `if (res.code === 401)` 就清 token 跳登录。

### 三层职责

- **Service 层抛异常**，不返回 `Result`
- **Controller 层只做三件事**：接参数 → 调 Service → 包 `Result`
- **GlobalExceptionHandler 统一转**

> [!warning] 为什么 Service 不返回 Result
> `Result` 是 HTTP 响应格式，Service 返回它意味着业务层依赖 Web 层。而且业务逻辑会被 `if (失败) return Result.fail()` 淹没，嵌套调用时每层都要判断返回值。用异常可以让任意深度直接中断。

## 三、2.1 注册

`POST /api/user/register` → `{username, password, nickname}`

### Service 五步

1. 判空（`StringUtils.hasText` 同时挡 null / `""` / 纯空格）
2. 查重 `selectCount(...eq(User::getUsername, ...))`
3. 重复抛 `USERNAME_EXISTS`
4. 组装实体：`password` 用 `passwordEncoder.encode()`，`nickname` 空则兜底用 `username`，`role=0` / `status=1` 显式设置
5. `userMapper.insert(user)`

### 关键设计

- **`createTime` / `updateTime` / `deleted` 不用 set**：建表时有 `DEFAULT CURRENT_TIMESTAMP` / `ON UPDATE` / `DEFAULT 0`，MyBatis-Plus 默认 `NOT_NULL` 策略不会把 null 写进 INSERT，数据库默认值兜底
- **`nickname` 必须兜底**：前端注册页只有 username / password / confirm 三个输入框，**根本不传 nickname**，不兜底就是 null
- **查重只是体验优化**：真正保证唯一的是数据库 `uk_username` 索引。并发场景下查重会漏，靠索引兜底
- 已知副作用：`uk_username` + 逻辑删除 → 账号被逻辑删除后同名无法再注册（insert 撞索引）

### 管理员账号

```sql
-- demo / 123456 / nickname=lzj / role=1
INSERT INTO `user` (username, password, nickname, role, status, deleted)
VALUES ('demo', '$2a$10$...', 'lzj', 1, 1, 0)
ON DUPLICATE KEY UPDATE password = VALUES(password), role = 1, status = 1, deleted = 0;
```

BCrypt 密文必须用项目同一个 `BCryptPasswordEncoder` 生成（长度 60，`$2a$10$` 开头）。

## 五、2.2 登录

`POST /api/user/login` → `{username, password}` → `{token, user}`

### Service 六步

1. 判空
2. `selectOne(...eq(User::getUsername, ...))` 按用户名查
3. **用户不存在 → 抛 `PASSWORD_ERROR`（不是 `USER_NOT_FOUND`）**
4. `passwordEncoder.matches(明文, 密文)` 校验密码
5. `status == 0` → `ACCOUNT_DISABLED`
6. 签发 token + 写 Redis + 组装 `LoginVO`

> [!important] 为什么用户不存在也返回"用户名或密码错误"
> 防止**用户名枚举**。如果明确说"用户不存在"，攻击者可以拿字典批量试探，摸出哪些账号真实存在，之后再针对这些账号撞密码，效率高一个数量级。

> [!important] 状态检查必须放密码校验之后
> 否则在对方还没证明身份时，就告诉了他"这个账号存在且被停用了"，同样泄露信息。**先证明你是谁，再告诉你账号状态。**

### JWT 工具类

```java
public String createToken(Long userId, String username, Integer role) {
    Date now = new Date();
    Date expiration = new Date(now.getTime() + expire * 1000L);  // 注意 1000L
    return Jwts.builder()
            .subject(String.valueOf(userId))
            .claim("username", username)
            .claim("role", role)
            .issuedAt(now)
            .expiration(expiration)      // 传 Date，不是时间戳
            .signWith(key())              // 传 SecretKey，不是字符串
            .compact();
}

public Claims parseToken(String token) {   // 失败返回 null，不抛异常
    ...
    Jwts.parser().verifyWith(key()).build().parseSignedClaims(token).getPayload();
}
```

- `subject` 放 userId（token 的主体就是"某个用户"）
- `expire * 1000L` 必须是 long 运算，写 `1000` 遇到大值会 int 溢出成负数，token 一签发就过期
- 密钥 65 字符 → jjwt 自动选 **HS512**（不是 HS256）

### Redis 白名单

```java
stringRedisTemplate.opsForValue().set(
        "wardrobe:login:token:" + token,
        String.valueOf(user.getId()),
        userJwtUtil.getExpire(),      // 7200，从 yml 注入
        TimeUnit.SECONDS);
```

最终 Redis 命令：`SET "wardrobe:login:token:eyJ..." "3" EX 7200`

- 用 **`StringRedisTemplate`** 而不是 `RedisTemplate`：后者用 JDK 序列化，key 在 `redis-cli` 里是乱码
- value 只存 **userId**，因为 JWT payload 里已经有 username 和 role，Redis 只当"是否有效"的开关
- 用带 timeout 的 `set`，不要 `set` + `expire` 两步（非原子，中断会留下永不过期的 key = 安全事故）

### 为什么 JWT 还要配 Redis

| | JWT 单独 | + Redis 白名单 |
|---|---|---|
| 防伪造 | 可以 | 可以 |
| 验真伪要不要查库 | 不用（纯计算） | 要（多一次 Redis 查询） |
| 能主动踢人下线 | 不能 | 可以（删 key） |
| 改密码/封号立刻生效 | 不能 | 可以 |
| 退出登录 | 只能前端删本地 token，服务端管不了 | 删 key |

**JWT 证明这张凭证没被伪造，Redis 证明它现在还有效。**

## 七、踩坑记录（最有价值的部分）

### 1. Lombok 静默失效 → 接口全返 406

**现象**：所有接口返回 `406 Not Acceptable`，但错误页的 JSON 能正常输出。

**排查**：`javap -p -classpath target/classes ...Result` 发现 `@Data` 的 getter **一个都没生成**。Jackson 认为这个类没有可序列化属性，判定"无法写出"，Web 层抛 406。

**根因**：Maven 编译时 `JAVA_HOME` 没设好，落到了系统 PATH 里的 **JDK 25**。**从 JDK 23 起 javac 默认 `-proc:none`，注解处理器不再自动执行**，Lombok 静默失效——编译不报错，运行时才炸。

**修复**：pom 里显式声明注解处理器

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <annotationProcessorPaths>
            <path>
                <groupId>org.projectlombok</groupId>
                <artifactId>lombok</artifactId>
            </path>
        </annotationProcessorPaths>
    </configuration>
</plugin>
```

**教训**：`@Data` 全线失效时编译器是安静的。凡是"编译过了但运行时行为诡异"，先 `javap` 看看 class 里到底有什么。

### 2. HikariCP 懒加载 → 假的"启动成功"

配了 `hikari.initialization-fail-timeout: -1`，连接池完全懒加载。**没有任何代码请求连接时，连接池根本不创建**，即使数据库密码填错了也会显示"启动成功"。

**修复**：加了 `/api/health/db` 主动执行 `select 1`，才算真正验证过。验证结果：

```json
{"code":200,"data":{"select1":1,"mysqlVersion":"8.0.33","database":"virtual_wardrobe","tableCount":6}}
```

### 3. Knife4j 的两个版本陷阱

- **groupId 变了**：4.5.0 起从 `com.github.xiaoymin` 改成 **`com.github.xingfudeshi`**，网上教程全是旧坐标，写错下载不到
- **4.4.0 及更早版本自带 springdoc 太旧**，和 Spring Framework 6.2+ 不兼容，启动报 `NoSuchMethodError`，必须用 4.6.0

### 4. jjwt 0.12.x 的 API 和网上教程完全不同

苍穹外卖、黑马点评用的都是 **0.9.1**，照抄必编译失败：

| 0.9.x | 0.12.x |
|---|---|
| `setSubject(...)` | `subject(...)` |
| `setClaims(...)` | `claims(...)` |
| `setExpiration(Date)` | `expiration(Date)` |
| `setSigningKey(...)` | `verifyWith(...)` |
| `signWith(SignatureAlgorithm, byte[])` | `signWith(SecretKey)` |
| `parseClaimsJws(token).getBody()` | `parseSignedClaims(token).getPayload()` |

另外 HS 算法要求密钥 **至少 32 字节**，太短第一次签发时抛 `WeakKeyException`。

### 5. GlobalExceptionHandler 漏了 `@RestControllerAdvice`

只写了方法上的 `@ExceptionHandler`，类上没加 `@RestControllerAdvice`。这样它只是个普通 Java 类，**注解完全不生效**，异常照样走 Spring 默认的 500。

### 6. `void` 方法不能 `return` 值

`public void register(...)` 里写 `return Result.fail("...")` 编译不过。真正的解法不是改返回类型，而是**用异常**（见第二节）。

### 7. Spring Boot 3 的 Redis 配置前缀变了

黑马点评是 `spring.redis`（Boot 2.x），Boot 3 必须写 **`spring.data.redis`**。

写错的话配置**被静默忽略**，客户端连的还是默认 `localhost:6379`，报连接超时，而报错信息里完全不会提配置写错了。

### 8. 前端读的是响应体里的 code，不是 HTTP 状态码

`utils/request.js`：

```js
if (res.code !== 200) {
  if (res.code === 401) { 清 token; 跳登录 }
}
```

这个 `res.code` 来自**响应体 JSON**，不是 HTTP 状态码。所以后端返回 HTTP 401 时，axios 会走 `error` 分支，清 token 跳登录的逻辑**根本不会执行**。

> [!warning] 2.3 必须注意
> 未认证时返回 **HTTP 200 + body `{"code":401,"message":"未登录"}`**。反常规但必须配合前端。

### 9. MySQL 8 的 `VALUES()` 被废弃

`ON DUPLICATE KEY UPDATE password = VALUES(password)` 在 8.0.20+ 会弹 `deprecated` 警告，**不影响执行**。想消掉警告可以用 `AS new` 别名语法。

## 八、关键决策清单（答辩可能问）

| 决策 | 选择 | 理由 |
|---|---|---|
| 主键 | `BIGINT AUTO_INCREMENT` | 雪花 ID 是 19 位，超出 JS `Number.MAX_SAFE_INTEGER`，前端会精度丢失 |
| 密码存储 | BCrypt | 自带随机盐、可调计算强度、抗彩虹表。MD5 无盐已被淘汰 |
| 鉴权 | JWT + Redis 白名单 | 兼顾"免查库验真伪"和"能主动作废" |
| 注入方式 | 构造器注入 | 字段可 `final`、依赖缺失编译期就报错、便于单测 |
| 逻辑删除范围 | 只给三张主体表 | `outfit_item` 有唯一索引，逻辑删除会和索引打架 |
| 错误码 | 分段枚举 | 看到 code 就知道哪个模块，前端可按区间处理 |
| 季节存储 | 位标识 1/2/4/8 | 一条记录存多选，`season & ? != 0` 即可查询，不用开关联表 |
| 接口前缀 | `context-path: /api` | 前端 vite 代理 `/api` 不做 rewrite |
| Redis 库 | 1 号库 + 项目前缀 | 0 号库给黑马点评；将来上云只有单库，靠前缀区分 |
